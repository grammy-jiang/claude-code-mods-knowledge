# P4/P5 ChatGPT Chat mode 验收记录 — 2026-10-14

## 实际验证与结论

ChatGPT 账号已经安装并启用 `claude-code-mods-knowledge` 插件 v0.1.0-rc.2，包含一个启用的 `claude-code-mods-development` Skill。该账号的 **普通 Chat mode** 已通过 Raspberry Pi 上已登录的专用浏览器发起多轮真实对话；并非 ChatGPT Work 模式。

ChatGPT 账号自己的插件读回操作确认了独立插件身份、版本、安装和 Skill 开启状态。账号插件管理器返回 `installed=yes` 和 `status=ENABLED`。插件在包管理器中的可见性与真实会话自动使用不是同一个质量门禁。

## 模型测试结果

- P4 场景：46 个（30 正向/多领域、8 无关负向、8 版本和安全边界）；离线资源检查 **46/46 通过**。离线结果不证明模型行为。
- rc.1 实际普通 Chat mode 正向事件测试：Skill 确实自动读取了官方参考文档，但回答生成了缺少 `$` 的错误事件处理器回调。对此新增了来自 M003 官方规范、审查通过的 K-0031，并增加回归检查。
- rc.2 实际普通 Chat mode：**7 个会话观测**（其中一次显式触发、6 次自动路由/未指定插件）。结构性评估 **3 pass / 4 fail**，包括模型未加载 Skill 的情况。这个评估不是 46 项整体问答通过率。
- rc.2 的 K-0031 显式调用测试通过：`on('tool.call', async ($, e, next) => { return next(e) })`，并正确引用 K-0031/M003 官方链接，来自真实 `api_tool.read_resource` 记录。
- rc.2 的未显式调用事件题在一次会话中**没有加载插件**；状态管理自动触发一次成功；安全自动触发一次成功，但严格评分认为没有引用期望的 K-0023；普通 HVAC 问题没有触发插件；新版本和历史边界问题虽然谨慎回答，仍未读取插件内容。

真实会话详细的只含 SHA 指纹和资源调用 URI 的脱敏证据：`docs/reports/p5_chat_mode_rc2_observations.json`。其中 **不会**保存完整聊天原文、敏感会话 ID 或账号凭据。证据结构评分仅根据实际加载事件、预期 Claim、官方引用、代码参数顺序判断，不是全量语义代码审查。

示例可直接在 ChatGPT 用户账号查看：成功的 [rc.2 显式调用事件测试](https://chatgpt.com/c/6aceaa2c-38a0-83ec-97ea-e0a323d7e0f0) 和首次暴露错误的 [rc.1 自动触发测试](https://chatgpt.com/c/6acea5af-7a68-83ec-9c3c-6f10b2c31888)。

## 三设备独立测试

在开发基线 Git `b15034f321e56199d54d9f9a838d2991eab4b44a`，三设备分别执行 233 项 Python 测试；MacBook Pro/macOS ARM64、raspberrypi/Linux ARM64、sextant/Linux ARM64 各自生成两个字节完全一致的 ZIP，48 个载荷文件 SHA-256 校验通过。

后续发布时**必须**对最终 Git Commit 重新执行三设备验收，才能将三台机器与 Release 的同一 `source_revision`/ZIP SHA 绑定。历史基线留在 `docs/reports/p5_three_host_initial_baseline_de2189b.json`。最终发布专用 P5 Host Matrix 由编译后生成在被 Git 忽略的 `release/` 文件夹，防止将矩阵中自身的 Git Commit 哈希写进 Git 导致循环变化。

整个三设备静态阶段均未调用 Claude Code/Codex/Pi Agent 模型；它们的 Token-based Skills 加载与真实模型测试仍待额度恢复。Raspberry Pi 发起的 ChatGPT Chat mode 测试则使用登录的 ChatGPT Pro 账号进行了真实模型对话。
